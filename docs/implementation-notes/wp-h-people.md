# WP-H: people, members, tasks and committees

Implements the people/identity findings of the PGAIR audit (`ui-people` P1–P5, P7, P8, P10–P18) and schema findings A2, B1, B2, B6 and B10. Excluded by assignment: P6 (task description editor, WP-A), P9 and P19 (meetings package), P20 (governance package). All schema changes are optional fields or a new table, so existing rows and old backups still restore.

## Assumptions and decisions

- A merge never deletes a profile; the tombstone keeps old links working and makes undo exact. Undo leaves alone any reference changed after the merge.
- Duplicate suggestions are only suggestions; "Joe"/"John" is not treated as a nickname pair.
- Historical source actions are recognised by the `historical-source-action` tag. Consolidation is explicit (a button with a preview), not automatic; it deletes folded duplicates only after copying their observations.
- Roster observations never create active directors or confirmed committee members: rosters become pending committee members, board rosters become `NeedsReview` directors on request.
- "Current representative" = live representative observations, or, when a seat has only roster contacts, those observed on the latest roster date.
- An organization member is a `members` row with `memberKind: "organization"` (`firstName` holds the name for existing list views, `lastName` is empty).
- Add to society as Director creates an Active register entry because the person adding it asserts the appointment; roster promotion uses NeedsReview because a roster is weaker evidence.
