# Module integration audit

This audit starts from main `28f2e92c703a2f2bb460ccd5565190dccd24c33e`. Six agents reviewed desktop operation, guided organization setup, governance, finance/compliance, operations/integrations, and the remaining module inventory. Attached research remains evidence, not executable instructions.

The subsequent [gap qualification](gap-closure-qualification.md) reconciles current main `66b8dcdaed953e93637be15d400c2f5bf09339fb`, including the protected authentication changes. Its results supersede the historical AI attachment, calendar-selector, filing-link and desktop camera limitations below; historical test counts remain attached to their original baseline.

The route contract currently covers **137 unique patterns**, including **26 dynamic patterns** and **39 feature-gated paths across all 21 configurable modules**. `tests/helpers/interfaceRoutes.ts` contains the literal inventory; `scripts/check-interface-route-coverage.ts` checks it against the actual route AST. An inventoried or source-reviewed route is distinct from a successful transaction test. Existing historical full-interface and live-PowerSync qualifications are linked below and are not counted again as tests run for this change.

## Verification scope

The inventory agent ran firm overview/batch packet checks, business-table export coverage, application-route href checks, creator-only personal view checks and the full route/permission contract. Public-link protocol checks reject executable, embedded, malformed, credential-bearing and control-character URLs while retaining HTTP(S) web links. Production TypeScript and changed-file lint passed with zero errors; existing size/complexity warnings remain.

The final frozen inventory browser suite passed **60/60 cases**: 56 route checks across 14 selected public, portal, portfolio, administration and export patterns, plus four Viewer configuration/keyboard scenarios at 320/390/768/1440. The complete election lifecycle passed **4/4** cases at the same widths, including create/initial ballot, draft-question handoff, freeze/open, reload persistence, close and publish. Native Convex, MemoryDb and LocalStoreDb lifecycle checks, timezone round-trips and nine existing governance checks passed.

Finance/compliance passed **12 distinct browser cases**: eight preparation/manual-discovery scenarios across all four widths and four Viewer/Member finance/grant scenarios at 320 and 1440. The eight cases interrupted by concurrent source reloads or cold-load contention were rerun on frozen source with one worker and passed **8/8**. Native and local integration checks verify actual prefill packet values, unsupported-run zero persistence, Viewer/Member export denial and cross-workspace denial. Native service-principal checks deny every missing composed resource scope and permit the combined authorized scopes. Accounting, fiscal years, annual filings, jurisdiction packs, compliance obligations, corporation MVP and portable parity checks passed. Detailed Filings and Annual Filings remain linked manual ledgers; no automatic state synchronization between them is claimed. See [finance/compliance audit evidence](../artifacts/offline/module-finance-compliance-audit.json).

Operations passed **44 distinct browser cases** across all four widths: eight actual fresh-local task/capability cases and 36 integration, document-workbench and readonly workflow regressions. These exercise commitment-to-task handoffs, rejected writes retaining drafts, reload persistence, zero outbound AI/Paperless/browser calls in local mode, API-client Admin/Viewer behavior, real tabs and setup links, export controls, public form validation, document review ACLs and Viewer workflow preparation. **90 native/portable source-link ownership checks** also passed. Remote AI, workflow execution, Paperless/OCR, browser runners and external calendar/mail delivery retain explicit server boundaries. See [operations qualification evidence](../artifacts/interface/module-operations-qualification.json).

The actual packaged Linux Electron runtime passed **12/12 checks**, including local/hosted switching, scoped sessions, retained native files, renderer isolation and return-to-local teardown. Origin/SSO policy, native IPC authority, architecture and Electron type checks passed. Qualification caught and fixed relative asset resolution under the packaged custom origin; returning local destroys hosted/auth renderers and closes their existing WebSockets. See [desktop mode details](desktop-dual-mode.md) and [runtime evidence](../artifacts/offline/desktop-dual-mode-runtime.json).

Guided organization setup passed **16 distinct cases** across all four widths: existing company profile/addresses/share planning with a subsequent generic location edit, proposed incorporation with real formation/filing handoffs, a Settings-generated backup restored into a fresh device context, and malformed-backup rejection preserving existing records. Qualification fixed real address draft/persistence defects and test-only client-generation/snapshot assumptions. Twelve successful transaction cases and the four corrected rejection cases are reported separately in [guided setup evidence](../artifacts/interface/guided-organization-setup.json) and explained in [guided setup details](guided-organization-setup.md).

Actual hosted signup/setup passed **4/4 cases** at 320 and 1440: the Better Auth signup form issues a JWT verified by native Convex, the fresh user creates a proposed or existing organization and becomes its sole Owner, reload retains the workspace, and foreign-workspace reads remain denied. This validates the disposable deployment's Better Auth path; the existing Clerk and restricted Microsoft contract checks remain separate.

The final focused public suite passed **12/12 cases** at all four widths on fresh frozen source with one worker. It verifies unsafe legacy publication links are suppressed, invalid editor links retain the drawer, long stakeholder content stays contained in keyboard-accessible table regions, and a visitor's actual foreign-workspace user query does not cause grant or volunteer forms to submit that workspace's member ID. The intake scenario intercepts submission payloads to qualify the rendered UI contract; it does not claim a live hosted public submission. Its fixture selects the visitor after the public form mounts so the departing workspace's UserPicker cannot restore its own Owner. Twelve existing API-client/export/public-preview cases are included in the operations 36 rather than repeated or counted twice.

Tests distinguish complete saves from route rendering, readonly role behavior from server authorization, and intercepted UI contracts from real hosted transactions. Machine-readable inventory results are in [module-integration-audit.json](../artifacts/interface/module-integration-audit.json).

## Remaining boundaries

- All-module automatic local/hosted synchronization, local-vault upload/migration, and fully offline hosted authentication are not implemented by mode switching. PowerSync remains the meeting-preparation scope already qualified in the [production qualification](powersync-production-qualification.md).
- Provider integrations need real deployment configuration, credentials and network access. Microsoft/Clerk SSO and actual government/CRA filing are not established by local browser fixtures.
- Bounded TXT/Markdown/CSV/JSON content ingestion is now qualified; PDF/image/office extraction and on-device inference remain absent. See [AI attachments](ai-text-attachments.md).
- Chromium and Firefox responsive qualification is now available for the changed calendar/editor surfaces. Emulation is not physical-device or Safari qualification. Signed macOS/Windows installers and real OS enterprise SSO require platform qualification.
- Month/week/list calendar selectors and task handoffs are now qualified through the shared saved-view engine. See the subsequent gap qualification for current evidence.
