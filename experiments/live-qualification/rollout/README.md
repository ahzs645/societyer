# Production PowerSync transport qualification on an isolated HTTPS lab

This runs the actual root application, native root Convex exports, existing Better Auth broker and pinned experimental PowerSync Convex connector. It does not deploy to a public server or use the pilot signer. The production credential route keeps its normal HTTPS, same-origin, membership, module, identity, short lifetime and rate-limit requirements.

First complete the base `experiments/live-qualification/README.md` setup and seed steps. Its existing native backend must run on loopback `43230/43231`, with eight disposable Better Auth accounts and an ignored `.env.accounts.local`. Stop concurrent base HTTP authorization/browser tests during the temporary issuer migration; their account bindings and native auth configuration are restored afterward. Existing user IDs, roles and document/material grants are retained.

From the repository root:

1. `node experiments/live-qualification/rollout.mjs prepare` generates a disposable two-day certificate, makes a consistent SQLite copy of the actual Better Auth accounts/signing keys and stores a separate private PowerSync database password. All generated files live under ignored `tmp/offline-rollout-tls`.
2. In separate terminals run `node experiments/live-qualification/rollout.mjs proxy`, `... auth`, and `... web`. The frontend is frozen without HMR; restart `web` after source changes. The actual application is served at `https://societyer-qualification.test:43479`; PowerSync is served at `https://sync-qualification.test:43229`. The upstream frontend/broker use `43478/43488`.
3. `node experiments/live-qualification/rollout.mjs sync` starts a separate pinned PowerSync service and PostgreSQL volume. Its Convex source attaches to the native backend's Docker network rather than trying to reach the host's loopback-only published port. Public lab TLS listeners bind loopback only. The server's internal JWKS request goes to the existing production signer over the private Docker host path.
4. `node experiments/live-qualification/rollout.mjs deploy` deploys the actual root exports and internal-only qualification helpers with the preparation feature enabled, temporarily selects the HTTPS issuer, then migrates exactly the eight disposable user bindings. No public helper can mint an identity, change a role or run the migration.
5. `node experiments/live-qualification/rollout.mjs test` runs both browser suites at 320, 390, 768 and 1440px. The launcher adds local-only DNS mappings, extends the inherited proxy bypass for these two local domains and narrowly pins the generated certificate's public key. It does not globally disable TLS verification or weaken production origin checks. Add `offline-rollout-production.spec.ts` or `offline-rollout-recovery.spec.ts` after `test` to run one suite. `OFFLINE_ROLLOUT_OUTPUT` and `OFFLINE_ROLLOUT_REPORT` select ignored evidence paths.
6. Run `node experiments/live-qualification/rollout.mjs cleanup`, then **`node experiments/live-qualification/rollout.mjs restore`**, even when a browser check fails. Cleanup deletes only labelled disposable meeting graphs; restore selects the original HTTP lab issuer and restores the same eight user bindings. Re-run a base actual-login/API check afterward.
7. Stop the three foreground processes with their terminal interrupts; `node experiments/live-qualification/rollout.mjs stop-sync` stops the extra replication services while retaining their isolated volume.

The launcher refuses any Convex URL/admin-key prefix outside this disposable native lab. `prepare` retains existing private files and PostgreSQL credentials; it never rotates a populated database password. After the two-day certificate expires, stop the lab processes before removing its disposable certificate/key files and rerunning preparation. Do not commit generated keys, certificates, SQLite databases, env files, cookies, JWTs or Playwright traces.

The production browser suite independently reads the actual SDK `offlineMeetingDownloads` SQLite table. Native authorized-snapshot hydration alone cannot satisfy replication checks. It exercises the actual broker, native domain commands, native storage HTTP bytes, all five roles, foreign-workspace credential denial, offline parent/child reconnection, stale minutes conflicts, dependency quarantine, material ACL withdrawal and scheduled expiry. The separate recovery suite runs the actual SDK WASM/SQLite/outbox with deliberately injected transport outcomes; those are durable client contracts, not additional live API tests.

The lab does not add COOP/COEP headers: the selected IndexedDB atomic VFS works with production's existing header policy. External Clerk/Microsoft logins, physical devices, Safari and packaged Electron remain outside this lab.

The root application requires an initialized authenticated page for offline preparation. Its web shell/auth gate is not a qualified offline navigation/authentication cache. An offline hard reload, a new offline tab or an expired session can require returning online to load/re-authenticate; authored SQLite commands and recovery persist. The standalone pilot's PWA reload proof does not establish that behavior for the root application. No cached actor is promoted into a verified hosted principal to work around that limit.
